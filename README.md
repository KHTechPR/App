# 新聞資訊上架申請表（BC03）

國立高雄科技大學秘書室公關中心「新聞資訊上架申請表」線上版，依 BC03 新聞稿發佈及新媒體整合應用作業程序（115.10.28）及新聞稿撰寫指引建置。

網址：https://khtechpr.github.io/App/

## Repository 內的檔案
- `index.html`：申請表網頁
- `BC03-writing-guide.pdf`：新聞稿撰寫指引（網頁上的下載連結指向此檔名）
- `README.md`：本說明
- `高科大NKUST.png`：表頭 logo（檔名不可更改）
- `SuperNorth-header.png`：表頭與媒體超人吉祥物（去背版）
- `SuperNorth.png`：吉祥物原圖（去背版不存在時的備用）
- `ticker.xlsx`：AI 等待時的輪播字幕（可選，沒有此檔就用網頁內建字幕）

`nkust-pr-backend.gs` 不放在 repository，它是貼到 Google Apps Script 使用的，裡面不含任何 key。

## 後端設定（照片上傳＋內建高科iAI，bcoffice03 帳號）

1. 以 bcoffice03@nkust.edu.tw 登入 Google Drive，建立資料夾「新聞資訊上架申請」。
   - 右鍵 → 共用，把公關中心同仁加為「編輯者」。
   - 開啟資料夾，複製網址 `drive.google.com/drive/folders/` 後面那一串（資料夾 ID）。
2. 同一帳號前往 https://script.google.com → 新專案，命名「新聞上架申請後端」。
   - 刪除預設內容，貼上 `nkust-pr-backend.gs` 全文。
   - 把 `請貼上根資料夾ID` 換成步驟 1 的資料夾 ID，按儲存。
3. 存入高科iAI API key（key 只存在這裡，不會出現在網頁）：
   - 左側齒輪「專案設定」→ 最下方「指令碼屬性」→「新增指令碼屬性」
   - 屬性：`IAI_KEY`　值：貼上你的高科iAI API key → 儲存
4. 回到編輯器，上方函式選 `testSetup` → 執行 → 依提示授權（出現「Google 尚未驗證這個應用程式」時按「進階」→「前往」）。
   - 執行記錄應依序出現：根資料夾名稱、可用模型、iAI 測試回覆。
   - 若卡在 iAI 測試（逾時或連線錯誤），代表 Google 的伺服器連不到高科iAI（可能只開放校園網路），請洽電算中心。
5. 右上「部署」→「新增部署作業」→ 齒輪選「網頁應用程式」。
   - 執行身分：我（bcoffice03@nkust.edu.tw）；誰可以存取：**任何人** → 部署
   - 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。
6. 打開 `index.html`，找到 `BACKEND_URL: ''`，把網址貼在兩個單引號中間，存檔後上傳到 GitHub 覆蓋。
7. 到申請網頁測試：AI 撰稿不需要再輸入 key；上傳一張照片，確認 Drive 出現「日期_單位_活動名稱」子資料夾。

注意：
- 若步驟 5 沒有「任何人」可選，代表學校 Google Workspace 管理設定不允許，需請電算中心開放。
- 之後修改程式要沿用同一個網址：部署 → 管理部署作業 → 鉛筆圖示 → 版本選「新版本」→ 部署。
- 更換 iAI key 只要改指令碼屬性 `IAI_KEY`，不用重新部署。
- 全站 AI 每日上限 300 次（程式內 `AI_DAILY_LIMIT` 可調整），避免額度被耗盡。
- 照片會佔用 bcoffice03 的雲端空間，請定期整理。

## 修改規則
期限天數、收件人、圖說字數、照片張數與大小上限，集中在 `index.html` 的 `CONFIG` 區塊。

## 高科iAI
後端設定完成後，AI 功能使用指令碼屬性中的 key，申請人只需在「AI 設定」選擇模型。後端未設定時，申請人需自行貼上 API key（網址與模型已預設為 `https://www.iai.nkust.edu.tw/aihub/v1`、`Furen-large`）。

## 等待字幕（ticker.xlsx）
- 第一個工作表 A 欄「類別」：新聞稿／社群貼文／檢視初稿／上傳照片／讀取資料／送出申請／換句秒數；B 欄「字幕」，一列一句；C 欄「出現頻率」（空白或 1＝一般，2＝兩倍，小於 1＝少見且每次等待最多一次，0＝暫停）。
- 修改後以同檔名上傳覆蓋即可，約 1–10 分鐘後生效；某類別留空則沿用內建字幕。

## 補件與修改（2026-11-01a 起）
- 每件新申請會產生「申請編號」（如 1101-AB3K），並記錄在根資料夾內自動建立的 Google 試算表「申請紀錄」。
- 通知信附「補件／修改連結」（`#photos=資料夾ID.驗證碼`），申請人點開即自動對應到原申請。

- 「修改原申請內容」會讀回資料夾內的「申請資料.json」，修改後產生「修訂版」申請表存入同一資料夾，並寄送修改通知。
- 更新前送出的舊申請沒有紀錄，請使用畫面上的「手動填寫」，會另建資料夾。
- 後端更新後須執行 `testSetup` 完成新的授權（試算表、Google 文件），再以「管理部署作業 → 新版本」發佈；網址列打開後端網址應顯示「程式版本：2026-11-20a」。
- 申請單位確認修訂稿（2026-11-13a 起）：公關中心存好修訂稿，並寄出附修訂稿連結的審核結果信後，申請人從補件／修改連結進入，會看到修訂對照，可逐處接受或拒絕、填寫意見後確認送出。確認後的定稿存為「新聞稿_申請單位確認定稿.docx」，並寄信通知新聞承辦；申請紀錄的「申請單位確認」欄會自動填入。公關中心若再修改修訂稿，申請人需要重新確認。
- 代為補傳照片（2026-11-13b 起）：申請單位用 Email 寄來的照片，公關同仁可在審核頁「代為補傳照片」上傳（新聞、社群、主任審核碼皆可）。照片存入原申請資料夾，檔名與申請人補件相同（補件月日-時分_圖N_原檔名），另存圖說文字檔；不佔申請單位的補傳次數；申請紀錄「備註」自動記下上傳者與照片來源；「寄信告知申請人」預設不勾選。
- 定稿文件（2026-11-18a 起）：每件申請在雲端資料夾有一份 Google 文件「【定稿】申請編號_活動名稱」，彙整最新文字（申請單位確認定稿 ＞ 公關修訂稿 ＞ 申請人最新內容）與所有照片、圖說。申請人修改或補件、公關存修訂稿或代傳照片、申請單位確認修訂稿時，都會覆寫同一份文件（連結不變）。審核頁按「🔒 定稿」（新聞同仁、社群同仁、主任），標記已上架時自動定稿；定稿後不再更新，申請人不能再修改或補傳，只有主任可以「解除定稿」。
- 用詞（2026-11-18b 起）：處理狀態「已核定」改為「已審核」，試算表「核定日期」欄改名「審核日期」（舊資料自動轉換）。審核清單分頁：待審核｜待派員（只有主任）｜需補件｜已審核｜已完成｜不予上架｜全部。
- 給申請人的說明（2026-11-18b 起）：寄出後鎖定成文字，只能新增「補充說明」；寄出 10 分鐘內可更正最後一則（不另寄信）。補寄只寄這次的補充說明；沒有新內容或評估結果沒變不能寄；同一件申請每天最多補寄 1 封，超過需主任審核碼。
- 照片檢查（2026-11-18c 起）：申請人選照片後會跳出「照片檢查」視窗，預設自動裁成橫式 3:2（可調整裁切範圍或改用原始照片），並檢查解析度（長邊 3000px）與直式照片，確認後才加入。上傳時畫面下方顯示進度條與跑馬字幕；字幕可在 ticker.xlsx 用類別「上傳照片」自訂。
- 定稿文件的照片與圖說（2026-11-18c 起）：審核頁「定稿文件」區列出這件申請的全部照片與圖說（含來源），預設不勾選；勾選「放入定稿」、用 ← → 調整順序、直接修改圖說，都會自動更新【定稿】文件。尚未勾選前，定稿文件先列出全部照片並標示「尚未選定」；之後補傳的照片會列出但不勾選。「🔒 定稿」按鈕在照片與圖說下方；定稿後照片與圖說鎖定。
- 刪除申請（2026-11-18d 起）：審核頁最下方「🗑 刪除這件申請」只有主任審核碼看得到；需輸入申請編號確認，會刪除申請紀錄試算表的那一列、把雲端資料夾移到垃圾桶（30 天內可從 Drive 垃圾桶救回）。
- 定稿文件照片表格（2026-11-18e 起）：【定稿】文件的照片改用表格排版，每列左邊「圖號＋照片」、右邊「圖說＋來源」，與申請表第六項相同。
- 定稿照片調整（2026-11-18f 起）：審核頁「照片與圖說」每張照片顯示尺寸與規格（3:2、長邊 3000px），可按「✂ 裁切」或「⇄ 換一張」（會先跳出照片檢查）。調整後的照片以「修圖月日-時分_」存入同一資料夾、取代原卡片並沿用勾選與圖說；原照片保留在資料夾但不再列出。
- 定稿照片資料夾（2026-11-19a 起）：按「🔒 定稿」（或標記已上架自動定稿）時，在原申請資料夾內建立「申請編號照片」資料夾，放入定稿的照片（已裁切、依定稿順序）複製為「申請編號_圖1.jpg…」，並附「申請編號_圖說.txt」；解除定稿後再定稿會重新整理。審核頁定稿區有資料夾連結。

- 稿件來回修改（2026-11-19b 起）：申請人從補件／修改連結進入，同一頁看到流程列與「現在需要你做的事」，公關中心的修改預設全部採用（綠色為新文字、刪除線為拿掉的文字），看過沒問題按「✓ 同意公關中心的修訂」即完成；不同意的地方點一下改回原文（也可「整段改回原文」），想自己改字按「✏️ 自己修改」，也可改圖說或把照片標成「不使用」（不刪除、可復原），再「送回公關中心」。申請人頁面上方顯示「七、公關中心評估意見」（只含已寄出的說明）。送回後存成「申請單位修改稿.json」，並寄信給承辦（「開啟審核頁查看修改」直達按鈕，同一件每天最多 1 封）。來回次數不設上限。
- 審核頁總覽卡：最上方顯示流程列、待辦（可「↓ 前往查看」）、稿件／照片／定稿文件／社群 4 個狀態，以及各區塊的快速跳轉；所有區塊都直接展開。「申請單位的修改」區塊以藍色顯示申請人的修改，可「✓ 接受」或「接受後再修訂」；接受後申請資料、定稿文件、照片勾選與圖說一併更新。
- 定稿前最後確認（不強制）：定稿區可按「📨 請申請單位做定稿前最後確認」，申請人收到綠色「檢視最終版本並確認」按鈕的信，看文字＋照片／圖說表後按「確認無誤，可以定稿」或「我要修改」。確認後審核頁顯示「✅ 申請單位已確認可以定稿」；未確認時按定稿會先提醒。給申請人的信同一件每天 1 封（主任可再寄）。
- 信件直達按鈕：首次申請通知信分「給申請人」（查看申請進度／補件／修改）與「給公關中心」（審核這件申請、開啟雲端資料夾）兩區；審核結果信一律附按鈕（附修訂稿時為「檢視修訂稿並確認／修改」）。
- 「待確認」分頁（2026-11-20a 起）：分頁順序為 待審核｜待派員（主任）｜需補件｜待確認｜已審核｜已完成｜不予上架｜全部。潤修後等申請單位確認修訂稿、等定稿前最後確認，以及申請單位已送回修改稿（紅色標示「請你確認」）的稿件放在這裡；照刊的稿件直接進「已審核」。
- 審核頁「七、公關中心評估意見」：已審核過的稿件，上方顯示「📋 已審核的意見」（評估結果、修訂稿狀態、校外稿、派員、給申請人的說明、內部備註），下方欄位仍可直接修正。
- 主任預覽申請人頁面（2026-11-20a 起）：用主任審核碼進入審核頁，總覽卡多一個「👁 申請人看到的頁面」，會另開分頁顯示申請人從補件／修改連結看到的畫面（上方紫色「主任預覽」提示）。可以點選查看，但所有送出、上傳按鈕都不會真的送出。新聞同仁、社群同仁看不到這個按鈕。
- 讀取中畫面與回清單（2026-11-20b 起）：審核頁點清單開啟申請時，會出現媒體超人「讀取中…」過場（字幕可在 ticker.xlsx 用「讀取資料」分類自訂）。審核頁底端連結一律為「← 回清單」。
## 送出前預覽與上傳順序（2026-11-01 起）
- 按「產生申請表」會先開啟 Word 申請表預覽，申請人確認後才送出。

## 調整申請項目（2026-11-23a 起）
- 申請人勾錯項目（例如該發校外稿卻勾校內稿、FB/IG 類型選錯）時，審核頁「申請資料」的「申請項目」欄按「調整申請項目」，改勾後填寫理由即可儲存。新聞、社群同仁與主任都可以調整全部項目。
- 調整後「申請項目」欄顯示目前項目（新加上的為藍色、拿掉的加刪除線），下方列出原申請與每次調整紀錄（時間、調整人、內容、理由）；申請紀錄試算表「申請項目」欄更新為調整後的項目，新增「申請項目調整」欄記錄原申請與調整歷程。
- 主任調整後鎖定：其他同仁只能查看，按鈕不再顯示；同仁先前的調整以刪除線保留。主任仍可再調整。（需設定 `DIRECTOR_PIN` 才能區分主任；未設定時新聞審核碼即為主任權限。）
- 新加上的項目會寄信通知該項目的承辦（新聞→新聞承辦，FB/IG→社群承辦；自己這一組加的不寄，主任加的都寄）。同一件申請、同一組承辦每天最多 1 封。
- 調整內容與理由不另寄給申請人，併入下一封審核結果信（「申請項目」「項目調整說明」兩列）；尚未告知的調整也算新內容，可補寄，但仍受每天 1 封的限制。
- 申請人之後修改申請內容時，保留公關中心調整後的項目；「授權撰寫社群貼文」「稿件後補」等標記依申請人最新填寫。
- 更新後端後請以「管理部署作業 → 新版本」發佈，後端網址應顯示「程式版本：2026-11-23a」。
