# 新聞資訊上架申請表（BC03）

國立高雄科技大學秘書室公關中心「新聞資訊上架申請表」線上版，依 BC03 新聞稿發佈及新媒體整合應用作業程序（115.10.28）及新聞稿撰寫指引建置。

網址：https://khtechpr.github.io/App/（原測試站：https://szu1104.github.io/NKUSTPR/）

## Repository 內的檔案
- `index.html`：申請表網頁
- `BC03-writing-guide.pdf`：新聞稿撰寫指引（網頁上的下載連結指向此檔名）
- `README.md`：本說明
- `高科大NKUST.png`：表頭 logo（檔名不可更改）
- `SuperNorth-header.png`：表頭與媒體超人吉祥物（去背版）
- `SuperNorth.png`：吉祥物原圖（去背版不存在時的備用）
- `ticker.xlsx`：AI 等待時的輪播字幕（可選，沒有此檔就用網頁內建字幕）

`nkust-pr-backend.gs` 不放在 repository，它是貼到 Google Apps Script 使用的，裡面不含任何 key。

## 後端設定（照片上傳＋內建高科iAI，bcoffice03 帳號）

1. 以 bcoffice03@nkust.edu.tw 登入 Google Drive，建立資料夾「新聞資訊上架申請」。
   - 右鍵 → 共用，把公關中心同仁加為「編輯者」。
   - 開啟資料夾，複製網址 `drive.google.com/drive/folders/` 後面那一串（資料夾 ID）。
2. 同一帳號前往 https://script.google.com → 新專案，命名「新聞上架申請後端」。
   - 刪除預設內容，貼上 `nkust-pr-backend.gs` 全文。
   - 把 `請貼上根資料夾ID` 換成步驟 1 的資料夾 ID，按儲存。
3. 存入高科iAI API key（key 只存在這裡，不會出現在網頁）：
   - 左側齒輪「專案設定」→ 最下方「指令碼屬性」→「新增指令碼屬性」
   - 屬性：`IAI_KEY`　值：貼上你的高科iAI API key → 儲存
4. 回到編輯器，上方函式選 `testSetup` → 執行 → 依提示授權（出現「Google 尚未驗證這個應用程式」時按「進階」→「前往」）。
   - 執行記錄應依序出現：根資料夾名稱、可用模型、iAI 測試回覆。
   - 若卡在 iAI 測試（逾時或連線錯誤），代表 Google 的伺服器連不到高科iAI（可能只開放校園網路），請洽電算中心。
5. 右上「部署」→「新增部署作業」→ 齒輪選「網頁應用程式」。
   - 執行身分：我（bcoffice03@nkust.edu.tw）；誰可以存取：**任何人** → 部署
   - 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。
6. 打開 `index.html`，找到 `BACKEND_URL: ''`，把網址貼在兩個單引號中間，存檔後上傳到 GitHub 覆蓋。
7. 到申請網頁測試：AI 撰稿不需要再輸入 key；上傳一張照片，確認 Drive 出現「日期_單位_活動名稱」子資料夾。

注意：
- 若步驟 5 沒有「任何人」可選，代表學校 Google Workspace 管理設定不允許，需請電算中心開放。
- 之後修改程式要沿用同一個網址：部署 → 管理部署作業 → 鉛筆圖示 → 版本選「新版本」→ 部署。
- 更換 iAI key 只要改指令碼屬性 `IAI_KEY`，不用重新部署。
- 全站 AI 每日上限 300 次（程式內 `AI_DAILY_LIMIT` 可調整），避免額度被耗盡。
- 照片會佔用 bcoffice03 的雲端空間，請定期整理。

## 修改規則
期限天數、收件人、圖說字數、照片張數與大小上限，集中在 `index.html` 的 `CONFIG` 區塊。

## 高科iAI
後端設定完成後，AI 功能使用指令碼屬性中的 key，申請人只需在「AI 設定」選擇模型。後端未設定時，申請人需自行貼上 API key（網址與模型已預設為 `https://www.iai.nkust.edu.tw/aihub/v1`、`Furen-large`）。

## 自動通知信（2026-10-31a 起）
- 產生申請表或補傳照片後，後端以 bcoffice03 帳號自動寄通知信給承辦人（依申請項目分流），申請人為副本，信件為簡短文字，附雲端資料夾連結（Word 申請表、照片都在資料夾內）。
- 收件人設定在 `nkust-pr-backend.gs` 的 `NOTIFY_ROUTES`；畫面上提醒申請人致電確認的聯絡方式在 `index.html` 的 `CONFIG.PHONES`。
- 更新後端後須在 Apps Script 執行一次 `testSetup`，授權「代表你傳送電子郵件」，再以「管理部署作業 → 新版本」發佈。
- 每日通知信上限 `NOTIFY_DAILY_LIMIT`（預設 150 封）；同一件申請只會寄一次。
- 若自動寄信失敗，網頁會改為顯示「用高科大 Gmail 寄信」按鈕。

## 等待字幕（ticker.xlsx）
- 第一個工作表 A 欄「類別」：新聞稿／社群貼文／檢視初稿／換句秒數；B 欄「字幕」，一列一句；C 欄「出現頻率」（空白或 1＝一般，2＝兩倍，小於 1＝少見且每次等待最多一次，0＝暫停）。
- 修改後以同檔名上傳覆蓋即可，約 1–10 分鐘後生效；某類別留空則沿用內建字幕。

## 補件與修改（2026-11-01a 起）
- 每件新申請會產生「申請編號」（如 1101-AB3K），並記錄在根資料夾內自動建立的 Google 試算表「申請紀錄」。
- 通知信附「補件／修改連結」（`#photos=資料夾ID.驗證碼`），申請人點開即自動對應到原申請。
- 「已提送申請」模式：Email＋申請編號可直接連結原申請；只填 Email 時，系統把申請清單與連結寄到該信箱（網頁不顯示，每小時最多 3 次）；補傳的照片存入原申請的同一個資料夾（檔名前綴「補件月日-時分_」），並寄送補件通知信（承辦人收件、申請人副本）。
- 「修改原申請內容」會讀回資料夾內的「申請資料.json」，修改後產生「修訂版」申請表存入同一資料夾，並寄送修改通知。
- 更新前送出的舊申請沒有紀錄，請使用畫面上的「手動填寫」，會另建資料夾。
- 後端更新後須執行 `testSetup` 完成新的授權（試算表），再以「管理部署作業 → 新版本」發佈；網址列打開後端網址應顯示「程式版本：2026-11-05d」。

## 送出前預覽與上傳順序（2026-11-01 起）
- 按「產生申請表」會先開啟 Word 申請表預覽，申請人確認後才送出。
- 送出順序：建立資料夾 → **申請表 Word（失敗自動重試一次）** → 照片／素材 → 申請資料.json → 通知信；畫面逐步顯示進度。
- 申請表未成功存入雲端時不會寄通知信，畫面顯示錯誤與「重新送出」按鈕（已完成的部分不重複上傳）。
